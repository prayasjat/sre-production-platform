# Incident INC-001

## Title

API Pod Failure

## Severity

SEV-3

## Impact

One API pod became unavailable.

The Kubernetes Deployment maintained service availability
through the remaining replica.

## Detection

Observed through Kubernetes pod status.

## Timeline

1. API deployment had 2 replicas.
2. One pod was manually deleted.
3. Kubernetes detected the replica mismatch.
4. Kubernetes created a replacement pod.
5. Service returned to desired state.

## Root Cause

Intentional failure injection for SRE testing.

## Recovery

Kubernetes self-healing automatically recreated the pod.

## Customer Impact

No expected outage because another replica remained available.

## Lessons Learned

- Multiple replicas improve availability.
- Readiness probes prevent unhealthy pods from receiving traffic.
- Kubernetes continuously reconciles desired and actual state.

## Follow-up

Add automated alerting and dashboards.
